Баланс Polza.ai и статистика расхода для Web GUI DeepSeek Harness.

Плагин показывает доступный баланс в футере сайдбара и открывает панель с расходом
по периодам, графиком по дням, разбивкой по моделям и историей генераций с
фильтрами.

## Что показывает

- **Баланс организации**: `amount`, `available`, резерв и всего потрачено.
- **Расход по ключу**: сегодня, с понедельника, за месяц, за всё время — точные
  цифры из `GET /api/v1/key`.
- **История**: график по дням, топ моделей, типы запросов, таблица генераций с
  фильтрами по типу, статусу и модели. Стоимость запроса показывается без
  округления до копеек, а при наведении раскрывается разбивка по токенам и
  строкам цены.
- **Лимит ключа**: остаток и период сброса, если лимит задан.

Баланс — общий по организации. История и расход — только по тому API-ключу,
которым пользуется DSH: Polza не отдаёт историю других ключей по API-ключу.

## Установка

Из npm:

```bash
dsh plugin --profile web add dsh-polza
```

Обновление до последней версии:

```bash
dsh plugin --profile web add dsh-polza@latest
```

Перезапустите `dsh web`. Плагин появится в футере сайдбара и в списке панелей.

Из GitHub — если нужна ветка `main` или конкретный коммит:

```bash
dsh plugin --profile web add github:XaPoHbomj/dsh-polza
```

Из локальной папки — для разработки:

```bash
dsh plugin --profile web add /path/to/dsh-polza
# или
dsh plugin --profile web add "link:$PWD"
```

Для разработки:

```bash
pnpm install
pnpm run build     # собирает lib/client.js
pnpm run watch     # пересобирает client при изменениях
```

Host-часть читается напрямую из `src/host`, перезапуск нужен только после её
изменений. Client-часть подхватывается HMR после пересборки.

## Ключ

Плагин не хранит ключ сам. Он разрешает ссылку через `ctx.credentials`:

```yaml
# ~/.dsh/.credentials.yaml
version: 1
refs:
  POLZA_API_KEY: pza_...
```

Порядок источников стандартный для DSH: сохранённый файл, окружение запуска,
`.env` проекта, `~/.dsh/.env`. Ключ остаётся на хосте и никогда не попадает в
браузер; в ответах и логах его нет.

Если нужен отдельный ключ только для статистики, заведите, например,
`POLZA_STATS_KEY` и укажите его в конфиге.

## Конфигурация

Строка плагина в профиле:

```yaml
- id: polza
  name: dsh-polza
  config:
    apiKeyRef: POLZA_API_KEY
    refreshSeconds: 60
    lowBalanceThreshold: 100
    criticalBalanceThreshold: 20
    historyMaxPages: 100
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `apiKeyRef` | `POLZA_API_KEY` | имя ссылки в credential-хранилище |
| `apiBaseUrl` | `https://polza.ai/api` | базовый URL Polza API |
| `routePrefix` | `/polza/api` | префикс read-only роутов |
| `refreshSeconds` | `60` | минимальный TTL кэша и автообновление чипа |
| `lowBalanceThreshold` | `100` | жёлтый порог баланса, ₽ |
| `criticalBalanceThreshold` | `20` | красный порог баланса, ₽ |
| `historyMaxPages` | `100` | сколько страниц по 100 записей читать для агрегатов |
| `requestTimeoutMs` | `15000` | таймаут одного запроса к Polza |
| `allowRemote` | `false` | разрешить роуты не только с loopback |

Поля `refreshSeconds`, `lowBalanceThreshold`, `criticalBalanceThreshold` и
`historyMaxPages` помечены как живые: их можно менять на странице
**Plugins → Polza** без перезапуска. Остальные поля применяются после
перезапуска профиля.

`historyMaxPages` ограничивает стоимость агрегатов. Если генераций за период
больше, панель показывает «частично», а точный итог берёт из сводки ключа.
Увеличение значения даёт более полный график и разбивку ценой большего числа
запросов к Polza.

## Локальный кэш истории

Завершённые и упавшие генерации не меняются, поэтому плагин сохраняет
нормализованные строки в локальный JSON-кэш:

```
~/.dsh/cache/dsh-polza/<fingerprint>.json
```

`<fingerprint>` — первые 20 символов SHA-256 от значения API-ключа. Сам ключ в
файл не попадает. При следующем открытии периода плагин загружает только первую
страницу истории (чтобы увидеть новые запросы), а остальное берёт из кэша. Это
убирает повторную загрузку тысяч записей при переключении «Неделя / Месяц» и
после перезапуска DSH.

- Кэшируются только `completed` и `failed`; `pending` каждый раз перечитывается.
- Файл ограничен 60 000 строк и хранит записи не старше 180 дней.
- Ошибка записи кэша не ломает панель: плагин просто работает без него.
- Смена ключа автоматически переключает кэш на новый fingerprint.

## Неофициальность

Это независимый open-source плагин. Он работает через публичный API Polza.ai,
который не является стабильным контрактом: поля, лимиты и поведение могут
измениться без предупреждения. Ни автор плагина, ни DeepSeek, ни Polza.ai не
несут ответственности за возможные ошибки в отображении баланса или расхода.
Сверяйте критичные суммы с официальным кабинетом.

## Безопасность

- Роуты только `GET`, без CORS-заголовков и с проверкой loopback.
- Ключ не логируется и не возвращается ни в одном ответе.
- `GET /v1/key` возвращает только маску ключа; она и показывается в шапке.
- Роуты read-only: плагин не пополняет баланс, не меняет ключи и лимиты.

## Метаданные истории и лимит 10 000

Polza отдаёт в `meta.total` и `meta.totalPages` не больше `10 000` и `100`
соответственно, даже когда записей больше. Это не жёсткий предел данных:
страницы после сотой продолжают возвращать строки, пока не встретится неполная
или пустая страница. Плагин больше не доверяет `totalPages` и читает историю
до фактического конца (в пределах `historyMaxPages`).

При этом `/v1/history/generations` с API-ключом показывает только генерации
этого ключа. Если в кабинете Polza счётчик больше, разница обычно приходится на
другие ключи, площадку или веб-использование — по API-ключу они недоступны.
Для истории всего аккаунта нужен JWT личного кабинета, который плагин
сознательно не использует.

## Релизы

Версия в `package.json`, git-тег `vX.Y.Z` и версия в npm должны совпадать.
Публикация запускается тегом:

```bash
npm version patch --no-git-tag-version
pnpm build
pnpm test
git add package.json lib/client.js
git commit -m "Release v0.1.1"
git tag -a v0.1.1 -m "v0.1.1"
git push origin main --follow-tags
```

После пуша workflow `Release` проверяет тег, собирает клиент, прогоняет тесты,
публикует пакет в npm и создаёт GitHub Release. Для публикации нужен секрет
репозитория `NPM_TOKEN` — granular access token с правом публикации `dsh-polza`.
Подробности — в [AGENTS.md](AGENTS.md).

## Ограничения

- Polza не отдаёт статистику по всем ключам аккаунта с API-ключом; для этого
  нужен JWT личного кабинета, которого плагин сознательно не использует.
- `available` может быть меньше `amount` из-за резерва под выполняющиеся запросы
  и лимитов ключа.
- Агрегаты по моделям и график строятся по загруженной части истории; точные
  итоги периода — по `/v1/key`.
